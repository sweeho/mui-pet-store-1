## catalog-browsing

### SWHM2-R-0147 · Storefront screens and populate tool

#### SWHM2-R-0147.02 · An anonymous caller is refused in production
- **SWHM2-C-0245** (integration, approved, v1) Populate endpoint refuses an anonymous caller in production and writes nothing
  - Preconditions: NODE_ENV is production. The test database has no category, product or item rows. The request has no admin_session cookie.
  - Step 1: Count the rows in the category, product and item tables.
  - Step 2: POST /api/catalog/populate with no cookie header.
  - Step 3: Read the response status.
  - Step 4: Count the rows in the category, product and item tables again.
  - Expected: The response status is 401, and the category, product and item row counts are the same as before the request (all zero).

#### SWHM2-R-0147.03 · An administrator loads the sample data in production
- **SWHM2-C-0246** (integration, approved, v1) Populate endpoint loads the sample catalog for an administrator in production
  - Preconditions: NODE_ENV is production. The catalog is empty. A valid administrator session exists (created with createAdminSession), and its id is sent in the admin_session cookie.
  - Step 1: POST /api/catalog/populate with the cookie header admin_session=<session id>.
  - Step 2: Read the response status and JSON body.
  - Step 3: Count the rows in the category, product and item tables.
  - Expected: The response status is 200. The body is { categories, products, items } with each count greater than zero, and each count equals the number of rows now in its table.

#### SWHM2-R-0147.04 · Any caller loads the sample data outside production
- **SWHM2-C-0247** (integration, approved, v1) Populate endpoint loads the sample catalog for an anonymous caller outside production
  - Preconditions: NODE_ENV is test (and, in a second run, development). The catalog is empty. The request has no admin_session cookie.
  - Step 1: POST /api/catalog/populate with no cookie header.
  - Step 2: Read the response status and JSON body.
  - Step 3: Count the rows in the category, product and item tables.
  - Expected: The response status is 200. The body reports categories, products and items counts greater than zero, and each count equals the number of rows now in its table.

#### SWHM2-R-0147.05 · The empty catalog does not advertise the endpoint
- **SWHM2-C-0248** (unit, approved, v1) Empty catalog page says the catalog is empty and does not mention the populate endpoint
  - Preconditions: The catalog view is rendered on page 1 with no categories (an empty entry list).
  - Step 1: Render the catalog list view (CategoryListView) for page 1 with an empty list of categories.
  - Step 2: Read the empty frame's title and message text.
  - Step 3: Search the rendered text for "populate" and "/api/catalog".
  - Expected: The empty frame shows the title "The catalog is empty", and no rendered text contains "populate" or "/api/catalog".

## site-shell

### SWHM2-R-0198 · Shell breadcrumb trail

#### SWHM2-R-0198.01 · A catalog detail page shows one trail
- **SWHM2-C-0249** (e2e, approved, v1) Item detail page shows only the Catalog path breadcrumb trail
  - Preconditions: The sample catalog is loaded, so item EST-24 exists.
  - Step 1: Open /catalog/items/EST-24.
  - Step 2: Find every element with the breadcrumb landmark (nav elements whose aria-label is "Breadcrumb" or "Catalog path").
  - Expected: Exactly one breadcrumb trail is on the page, and its aria-label is "Catalog path". No trail labelled "Breadcrumb" is shown.

#### SWHM2-R-0198.02 · Catalog search shows one trail
- **SWHM2-C-0250** (e2e, approved, v1) Catalog search page shows only the Catalog path breadcrumb trail
  - Preconditions: The sample catalog is loaded.
  - Step 1: Open /catalog/search?keyword=fish.
  - Step 2: Find every breadcrumb nav (aria-label "Breadcrumb" or "Catalog path").
  - Expected: Exactly one breadcrumb trail is on the page, and its aria-label is "Catalog path".

#### SWHM2-R-0198.03 · A path segment with no page is not a link
- **SWHM2-C-0251** (e2e, approved, v1) Order page shell trail shows Orders as plain text and has no link to a missing page
  - Preconditions: A signed-in customer has placed an order and has its id.
  - Step 1: Open /checkout/orders/<id> as that customer.
  - Step 2: Find the shell breadcrumb trail (aria-label "Breadcrumb").
  - Step 3: Read the "Orders" crumb and check whether it is a link.
  - Step 4: For each link in the trail, request its href and read the status.
  - Expected: The "Orders" crumb is plain text, not a link. No link in the trail leads to /checkout/orders, and every link in the trail opens a page that does not return 404.

#### SWHM2-R-0198.04 · Other multi-level pages keep their shell trail
- **SWHM2-C-0252** (e2e, approved, v1) Admin orders page keeps its shell trail with an Administration link to /admin
  - Preconditions: An administrator is signed in.
  - Step 1: Open /admin/orders.
  - Step 2: Find the shell breadcrumb trail (aria-label "Breadcrumb").
  - Step 3: Read the crumb texts in order.
  - Step 4: Read the href of the "Administration of orders" crumb.
  - Expected: The trail reads "Home / Administration of orders / Orders", and the "Administration of orders" crumb is a link to /admin.
